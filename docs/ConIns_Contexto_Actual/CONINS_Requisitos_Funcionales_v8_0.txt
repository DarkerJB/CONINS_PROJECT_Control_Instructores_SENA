Modulo AUTH — Autenticacion y gestion de cuentas

RF-01  El sistema debe implementar un proceso de registro en dos pasos: el
       administrador crea la cuenta del usuario en el sistema indicando
       nombre, correo, rol, tipo y numero de documento; el usuario, al
       acceder por primera vez, establece su contrasena mediante el
       endpoint de creacion de contrasena. Mientras no tenga contrasena
       asignada, el sistema retorna HTTP 403 e impide el acceso (RN-01).

RF-02  El sistema debe permitir el inicio de sesion con correo y contrasena,
       emitiendo un token JWT que incluye el identificador del usuario y
       su rol, con expiracion configurable. El sistema registra el ultimo
       acceso en el momento del login exitoso.

RF-03  El sistema debe permitir a cualquier usuario autenticado consultar y
       editar su propio perfil: nombre, tipo de documento (CC, CE, TI o
       pasaporte) y numero de documento.

RF-04  El sistema debe permitir recuperar la contrasena mediante un token
       de un solo uso con expiracion de una hora, enviado al correo
       registrado del usuario (condicionado a que SMTP este configurado),
       y restablecer la contrasena mediante ese token.

RF-05  El sistema debe permitir a cualquier usuario autenticado cambiar su
       contrasena ingresando la contrasena actual y la nueva.

RF-06  El sistema debe permitir a cualquier usuario cerrar sesion de forma
       segura descartando el token en el cliente.

RF-07  El sistema debe permitir a los administradores (Subdirector,
       Coordinadora Academica y Asistente de Coordinacion) crear nuevas
       cuentas de usuario, editar cuentas de usuarios de menor jerarquia,
       deshabilitar y reactivar cuentas, y consultar el historial de
       ultimo acceso de cada usuario del sistema.

Modulo INSTRUCTORES

RF-08  El sistema debe permitir a los administradores registrar instructores
       indicando el tipo de area (tecnica o transversal) como complemento
       al registro de su cuenta de usuario. El tipo de area determina la
       asignacion de competencias que puede impartir el instructor (RN-13).

RF-09  El sistema debe permitir a los administradores registrar y actualizar
       las competencias habilitadas para cada instructor, de manera que el
       sistema las filtre correctamente al momento de realizar asignaciones
       (RN-13).

RF-10  El sistema debe permitir a los administradores registrar una novedad
       administrativa para un instructor activo (licencia, incapacidad,
       comision u otra), indicando tipo de novedad, fecha de inicio, fecha
       estimada de regreso y observacion opcional. Mientras la novedad
       este vigente el instructor queda excluido de nuevas asignaciones
       (RN-08); al vencerse la fecha de regreso se reincorpora
       automaticamente.

RF-11  El sistema debe permitir a los administradores consultar y filtrar
       el listado de instructores por tipo de area, programa y estado.

RF-12  El sistema debe permitir a los administradores deshabilitar y
       reactivar instructores sin eliminarlos fisicamente, conservando
       su historial de asignaciones y novedades (RN-10).

========================================================================================

Modulo FICHAS

RF-13  El sistema debe permitir a los administradores registrar fichas de
       formacion indicando numero de ficha, programa, jornada, ambiente,
       etapa (lectiva o productiva), fecha de inicio y terminacion lectiva,
       e instructor lider (lider_id). La fecha de inicio de etapa
       productiva se registra cuando aplique.

RF-14  El sistema debe permitir a los administradores editar la informacion
       de una ficha registrada, incluyendo la actualizacion de etapa
       cuando el grupo avance de lectiva a productiva.

RF-15  El sistema debe permitir a los administradores finalizar o deshabilitar
       fichas de formacion sin eliminarlas fisicamente, conservando su
       historial de asignaciones y horarios (RN-10).

RF-16  El sistema debe permitir a los administradores consultar y filtrar
       el listado de fichas por programa, jornada, etapa, estado y
       ambiente asignado. Los instructores consultan unicamente las fichas
       a las que estan asignados.

RF-17  El sistema debe permitir a los administradores registrar una novedad
       administrativa sobre una ficha activa (comite de evaluacion, paro,
       actividad fuera del CDMC u otra), indicando tipo de novedad, fecha
       de inicio, fecha de regreso y observacion opcional. Mientras la
       novedad este vigente la ficha queda excluida de nuevas asignaciones
       de horarios; al vencerse la fecha de regreso se reincorpora
       automaticamente.

========================================================================================

Modulo PROGRAMAS

RF-18  El sistema debe permitir consultar el listado de programas de
       formacion disponibles con sus datos de tipo de linea (medular o
       transversal), tipo de area (tecnica o transversal) y modalidad,
       para uso en formularios de registro de fichas y asignaciones.

RF-19  El sistema debe permitir a los administradores registrar el instructor
       referente de cada programa de formacion (lider_programa) como dato
       organizativo e informativo, sin impacto en los permisos del sistema.

========================================================================================

Modulo AMBIENTES

RF-20  El sistema debe permitir a los administradores registrar y actualizar
       ambientes indicando nombre, tipo (fisico o virtual), capacidad y
       area a la que pertenece.

RF-21  El sistema debe permitir a los administradores deshabilitar y
       reactivar ambientes sin eliminarlos fisicamente (RN-10). Las fichas
       de modalidad virtual no requieren validacion de ambiente fisico
       (RN-14).

RF-22  El sistema debe permitir a los administradores consultar y filtrar
       el listado de ambientes por tipo, area y estado.

RF-23  El sistema debe permitir a los administradores registrar un bloqueo
       temporal de un ambiente indicando fecha de inicio, fecha de fin y
       motivo. Mientras el bloqueo este vigente el ambiente queda excluido
       de nuevas asignaciones de horarios (RN-09); al vencerse la fecha
       de fin se reincorpora automaticamente.

RF-24  El sistema debe permitir a los administradores consultar los bloqueos
       activos e historicos de cada ambiente.

========================================================================================

Modulo HORARIOS

RF-25  El sistema debe permitir a los administradores registrar bloques de
       horario asignados a una ficha, instructor y ambiente, asociados a
       una jornada y dia de la semana, con hora de inicio y hora de fin.
       Cada bloque inicia en estado pendiente.

RF-26  El sistema debe permitir a los administradores editar un bloque de
       horario existente. Al guardar, el sistema revalida automaticamente
       las reglas RN-03 (jornada restringida), RN-04 (solapamiento, hard),
       RN-05 (ambiente ocupado, soft) y RN-09 (ambiente bloqueado, hard)
       sobre los nuevos valores.

RF-27  El sistema debe permitir a los administradores deshabilitar un bloque
       de horario sin eliminarlo fisicamente, conservando trazabilidad del
       cambio (RN-10).

RF-28  El sistema debe permitir visualizar la malla de horarios de una ficha
       o instructor en formato de grilla semanal, mostrando jornada,
       ambiente e instructor asignado por dia y franja horaria.

RF-29  El sistema debe permitir a los administradores aprobar o rechazar
       bloques de horario en estado pendiente. El rechazo requiere motivo
       obligatorio. Un horario rechazado no suma a la carga horaria
       semanal del instructor.

RF-30  El sistema debe permitir a los administradores suspender un bloque
       de horario previamente aprobado, con motivo obligatorio, dejando
       trazabilidad del cambio de estado (suspendido con motivo).

RF-31  El sistema debe permitir categorizar cada bloque de horario mediante
       un tipo de actividad (Formacion Titulada, Disponible, Investigacion,
       Desarrollo Curricular, Etapa Practica, etc.), determinando si ese
       bloque suma o no a la carga horaria semanal del instructor segun
       el campo suma_carga_horaria del tipo de actividad seleccionado.

========================================================================================

Modulo ASIGNACIONES

RF-32  El sistema debe permitir a los administradores asignar un instructor
       a una ficha con una o mas competencias habilitadas, validando que:
       la competencia este autorizada para ese instructor (RN-13); ningun
       RAP de la nueva competencia este ya asignado a otro instructor en
       la misma ficha (RN-06, HTTP 409); y el instructor no tenga novedad
       administrativa vigente (RN-08). Los RAPs se heredan automaticamente
       al asignar la competencia; no se asignan individualmente (RN-15).

RF-33  El sistema debe permitir a los administradores registrar asignaciones
       provisionales de instructores a fichas fuera de su tipo de area,
       con autorizante, fecha y motivo obligatorios (RN-11). Solo los
       administradores pueden registrar asignaciones provisionales (RN-12).

RF-34  El sistema debe permitir a los administradores designar al instructor
       referente de una ficha activando el campo es_lider_ficha en la
       asignacion. Este campo es informativo y organizativo; no otorga
       permisos adicionales en el sistema.

RF-35  El sistema debe permitir a los administradores desactivar una
       asignacion, desactivando en cascada las competencias y horarios
       asociados y registrando el motivo (RN-10).

RF-36  El sistema debe permitir a los administradores y a los instructores
       consultar asignaciones activas, provisionales e historicas,
       filtradas segun el rol del usuario autenticado.

========================================================================================

Modulo ALERTAS Y NOTIFICACIONES

RF-37  El sistema debe emitir una alerta de tipo HORAS_EXCEDIDAS o
       HORAS_INSUFICIENTES cuando la carga horaria semanal de un instructor
       quede fuera del rango permitido (20 a 40 horas), sin bloquear el
       registro (RN-07, soft).

RF-38  El sistema debe emitir una alerta de tipo JORNADA_RESTRINGIDA cuando
       se registre un horario en jornada nocturna o fin de semana para
       cualquier instructor, sin bloquear el registro (RN-03, soft).

RF-39  El sistema debe emitir una alerta de tipo AMBIENTE_OCUPADO cuando
       el ambiente seleccionado ya este ocupado en la misma jornada y dia
       por otra ficha, sin bloquear el registro (RN-05, soft).

RF-40  El sistema debe bloquear el registro de un horario cuando genere
       solapamiento de franja horaria con otro horario activo del mismo
       instructor en el mismo dia y semana, retornando HTTP 409 con
       descripcion del conflicto (RN-04, hard block).

RF-41  El sistema debe notificar al instructor cuando se le asigne o
       modifique una competencia o ficha, o cuando se registre una novedad
       administrativa sobre su cuenta, mediante notificacion interna en el
       sistema y correo electronico al correo registrado (condicionado a
       SMTP configurado en el entorno).

RF-42  El sistema debe notificar a la Coordinadora Academica y al Asistente
       de Coordinacion cuando ocurra un cambio de asignacion o se registre
       una novedad en un instructor del programa ADSO, o cuando se registre
       una asignacion provisional, mediante notificacion interna.

RF-43  El sistema debe notificar a la Coordinadora Academica, al Asistente
       de Coordinacion y al Subdirector cuando se genere una alerta de
       carga horaria fuera de rango, una asignacion provisional o un
       bloqueo de ambiente, mediante notificacion interna.

========================================================================================

Modulo CONSULTA Y REPORTES

RF-44  El sistema debe mostrar un panel de carga horaria semanal por
       instructor con el total de horas asignadas comparado con el rango
       permitido (20 a 40 horas), con filtros por semana y programa.
       El Subdirector ve el CDMC completo; la Coordinadora Academica y el
       Asistente de Coordinacion ven el alcance ADSO; el Instructor ve
       unicamente sus propias fichas.

RF-45  El sistema debe permitir a los administradores consultar y filtrar
       informacion de instructores, programas, competencias, ambientes,
       fichas, jornadas y horarios desde vistas dedicadas.

RF-46  El sistema debe permitir a cualquier usuario autenticado consultar
       su historial de notificaciones recibidas, marcar notificaciones
       individuales o todas como leidas, y consultar el conteo de
       notificaciones no leidas.

RF-47  El sistema debe permitir a los administradores exportar la malla de
       horarios de una ficha o instructor en formato PDF para reportes,
       reuniones y evidencias de gestion.

========================================================================================

Modulo SEGURIDAD Y TRAZABILIDAD

RF-48  El sistema debe filtrar automaticamente los listados de horarios,
       fichas, asignaciones y alertas segun el rol del usuario autenticado:
       Subdirector recibe el dataset CDMC completo; Coordinadora Academica
       y Asistente de Coordinacion reciben el alcance ADSO; Instructor
       recibe unicamente los registros vinculados a su instructor_id.

RF-49  El sistema debe registrar automaticamente en una bitacora de auditoria
       cada operacion de creacion, modificacion o desactivacion realizada
       sobre datos del sistema, asociandola al usuario autenticado que la
       realizo, y permitir a los administradores consultar este historial.

RF-50  El sistema debe garantizar que toda la logica de negocio, validaciones
       de reglas y calculo de horas se ejecuten exclusivamente en el
       servidor. El frontend consume los endpoints y renderiza las
       respuestas; no implementa logica de negocio ni calcula carga
       horaria de forma independiente.

RF-51  El sistema debe proveer endpoints de catalogo de solo lectura para
       datos de referencia utilizados en formularios: areas, jornadas,
       tipos de novedad (instructor, ambiente, ficha), tipos de actividad,
       y listas de programas, competencias y RAPs filtrados por contexto.

========================================================================================

Modulo RAP-SEGUIMIENTO

RF-52  El sistema debe permitir a los administradores registrar y actualizar
       el seguimiento de resultados de aprendizaje (RAPs) por ficha y por
       asignacion_competencia, indicando fechas de inicio, fin y estado de
       avance. Los RAPs se heredan automaticamente al asignar una
       competencia y no se asignan individualmente (RN-15).

RF-53  El sistema debe permitir a los administradores evaluar el estado de
       aprobacion de cada RAP en seguimiento (pendiente, aprobado, no
       aprobado), activar o desactivar registros de seguimiento, y
       consultar los RAPs disponibles (sin seguimiento registrado) en
       una ficha.

Reglas de negocio de referencia (definicion completa en CONINS_Logica_Negocio_v5.md):
  RN-01  Onboarding dos pasos — sin password = HTTP 403
  RN-02  Correo como identificador unico del usuario
  RN-03  Alerta JORNADA_RESTRINGIDA cuando horario en nocturna o fin de semana (soft)
  RN-04  Hard block solapamiento de horarios del mismo instructor (HTTP 409)
  RN-05  Soft alert AMBIENTE_OCUPADO en la misma jornada y dia
  RN-06  Unicidad RAP por ficha — un RAP no puede quedar en dos instructores (HTTP 409)
  RN-07  Alerta CARGA_HORARIA cuando semana queda fuera de rango 20-40h (soft)
  RN-08  Novedad vigente excluye instructor de nuevas asignaciones
  RN-09  Bloqueo activo excluye ambiente de nuevas asignaciones de horario
  RN-10  Soft delete universal — activo = FALSE, nunca DELETE fisico en BD
  RN-11  Asignacion provisional requiere autorizante, fecha y motivo obligatorios
  RN-12  Solo administradores pueden registrar asignaciones provisionales
  RN-13  Competencia debe estar en instructor_competencias_habilitadas para asignar
  RN-14  Fichas virtuales no requieren ambiente fisico
  RN-15  RAPs se heredan automaticamente al asignar competencia; no se asignan uno a uno
  RN-16  Al cambiar instructor en asignacion_competencia activa, registrar
         instructor_anterior_id y fecha_cambio (trazabilidad)
  RN-17  Nomenclatura "ficha" configurable en frontend mediante terminology.ts

LIMITES DE CARGA HORARIA (confirmados 04/05/2026, aplican a todos los instructores):
  Minimo: 20 horas semanales
  Maximo: 40 horas semanales
